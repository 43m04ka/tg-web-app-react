# Изменения для фронта

Документ про правки, не связанные с кассой AuraPay — по ней отдельный файл `AURAPAY_FRONTEND.md`.

Дата: 13.08.2026

---

## Парс PlayStation переведён на GraphQL

PS Store перестала отдавать данные в HTML: в странице остались только меню и футер, а товары,
цены и описания подгружаются запросами уже в браузере. Из-за этого парс PS не работал совсем —
ни поверхностный, ни с заходом в карточку. Парсер переведён на тот же GraphQL, которым
пользуется сама витрина.

**Контракт данных товара не изменился** — поля карточки те же. Изменения касаются только формы
запуска парса PS в админке: три пункта ниже.

---

### 1. Ссылка каталога — только вида `/category/<id>`

Парсу нужен идентификатор категории, поэтому в поле каталога должна лежать ссылка вида

```
https://store.playstation.com/en-tr/category/b24c16e8-6475-4477-8364-41ec777792d5
```

Номер страницы в конце допустим — он игнорируется. Ссылки вида `/pages/deals` больше не годятся:
парс завершится с сообщением «нужна ссылка вида /category/<id>».

Раньше подходила почти любая ссылка листинга, поэтому это стоит подсветить в подсказке к полю.

---

### 2. `countPages` стал необязательным

```jsonc
POST /api/parse/ps
{
  "catalogId": "https://store.playstation.com/en-tr/category/<id>",
  "bdPath": "ps/games",
  "countPages": 0,          // 0 или пусто — вся категория целиком
  "isShallow": true,
  "parceAddons": false,
  "platform": "ps"
}
```

Раньше пустое значение отбивалось ошибкой «Не все поля заполнены»; обязательными остались только
`catalogId` и `bdPath`. Теперь `0`/пусто означает «парсить всю категорию» — сколько в ней страниц,
сервер спрашивает у витрины сам и пишет в лог и в прогресс задачи
(«В категории 4436 товаров — это 185 страниц»).

Поле можно оставить как есть, но подпись логично сменить на «Страниц (пусто — все)».

---

### 3. Новые необязательные поля: `filterBy` и `sortBy`

Витрина умеет фильтровать и сортировать на своей стороне — это дешевле, чем выкачать всё
и отбросить лишнее. Оба поля необязательны, поведение без них прежнее.

```jsonc
{
  "filterBy": ["storeDisplayClassification:FULL_GAME", "targetPlatforms:PS5"],
  "sortBy": {"name": "sales30", "isAscending": false}
}
```

Рабочие значения `filterBy` (счётчики — пример по категории со скидками, 4436 товаров):

| Группа | Значения |
|---|---|
| `storeDisplayClassification` | `FULL_GAME`, `GAME_BUNDLE`, `PREMIUM_EDITION`, `ADD-ON_PACK`, `LEVEL`, `OTHER` |
| `targetPlatforms` | `PS4`, `PS5` |
| `productGenres` | `ACTION`, `ADVENTURE`, `CASUAL`, `ARCADE`, `PUZZLE`, `SIMULATION`, … |
| `ageRating` | `PEGI_3`, `PEGI_7`, `PEGI_12`, `PEGI_16`, `PEGI_18` |
| `productVrCompatibility` | `PSVR`, `PSVR2` |

Значения внутри одной группы складываются по «или», разные группы — по «и»:
`FULL_GAME` + `PS5` дают 1527 товаров вместо 4436, то есть 64 страницы вместо 185.

Значения `sortBy.name`: `default`, `sales30` (по продажам), `downloads30`, `productName`,
`productReleaseDate`. Направление задаётся `isAscending`.

Минимально достаточный вариант для админки — два чекбокс-списка («Тип» и «Платформа») плюс
селект сортировки; остальные группы можно не выводить.

---

### 4. Дата окончания акции подтягивается сама

`endDataPromotion` в поверхностном парсе больше не обязателен. Если поле пустое, сервер сам
спрашивает дату у витрины и проставляет её товарам со скидкой.

В листинге даты нет вообще, поэтому она берётся из карточек: скидки в PS Store идут магазинными
кампаниями с общим сроком, и на каждой странице проверяются три товара со скидкой. Совпали —
дата применяется ко всей странице (это ~1 секунда на страницу из 24 товаров). Разошлись —
дата не проставляется вовсе, чтобы товару не достался чужой срок акции; в лог уходит
предупреждение.

Значение из формы имеет приоритет: если админ ввёл дату руками, используется она.
В интерфейсе поле логично подписать «Акция до (пусто — определить автоматически)».

---

### 5. Ошибки запуска стали содержательнее

Перед парсом сервер делает одну проверку витрины. Если PS Store сменила свои запросы или
категория не найдена, задача падает сразу с понятным текстом
(`Витрина PS Store недоступна для парса: …`), а не после тысяч ошибок по отдельным товарам.
Текст уходит в лог задачи — если админка его показывает, отдельной обработки не нужно.

---

### Что попутно стало лучше в данных

- Витрины-подборки (Latest, Collections) наконец парсятся: они отдают карточки «концептами»,
  и раньше такие категории давали ноль товаров при сотнях позиций внутри.
- `numberPlayers` берётся из структурного поля витрины, а не регуляркой из текста плашки —
  в фильтр каталога больше не может попасть число онлайн-слотов вместо локальных игроков.
- `typeLabel` не зависит от языка витрины: считается по машинному коду категории.
- Бесплатные и недоступные позиции («Free», «Included», «Unavailable») больше не превращаются
  в цену `0` — они корректно пропускаются.
