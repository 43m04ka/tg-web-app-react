# Дизайн-система админ-панели

Технический минимализм в духе панелей управления (ispmanager, reg.ru): плотная сетка,
спокойный нейтральный фон, один акцентный цвет, никаких градиентов и «свечения».
Иконки в навигации не используются — пункты меню различаются только текстом и состоянием.

Все токены живут в `styles/_tokens.scss` (миксин `admin-tokens`) и подключаются один раз
в `AdminPanel.module.scss` на `.themeRoot`. Тема переключается атрибутом `data-theme="light|dark"`.

> Правило: в компонентах админки **не хардкодим цвета/размеры** — только `var(--…)`.
> Новый оттенок → сначала токен, потом использование.

## Палитра

Акцент — «Aura Blue»: холодный синий, единственный носитель «фирменности».
Статусные цвета приглушены, чтобы не спорить с акцентом.

| Токен | Dark | Light | Назначение |
|---|---|---|---|
| `--bg` | `#0d1016` | `#f5f7fa` | фон рабочей области |
| `--surface` | `#12161f` | `#ffffff` | навбар, докобар |
| `--surface-alt` | `#171c27` | `#f0f3f8` | карточки, поля ввода, поповеры |
| `--surface-hover` | `#1c2230` | `#e9eef7` | ховер-подложка |
| `--border` | `#232936` | `#e3e8f0` | разделители, рамки |
| `--border-strong` | `#2f3746` | `#cfd7e3` | рамка в ховере, скроллбар |
| `--border-dashed` | `#3d4a63` | `#b3c0d6` | пунктирная обводка блоков |
| `--text` | `#eef1f6` | `#131722` | основной текст, заголовки |
| `--text-secondary` | `#b4bccb` | `#4a5567` | пункты меню, тело карточек |
| `--text-muted` | `#7c8697` | `#6b7688` | подписи, заголовки групп |
| `--accent` | `#4d7cfe` | `#2f5fe0` | активное состояние, ссылки, primary |

`--danger-rgb`: `background: rgba(var(--danger-rgb), 0.12)`.

## Типографика

`--font-ui` — **SF PRO Display** (тот же кастомный шрифт, что и в пользовательской части;
`@font-face` в `styles/adminFonts.css`, подключается из `AdminPanel.jsx`). Доступны только два
начертания — 400 и 700, поэтому промежуточные веса не используем. `--font-mono` — для ID, сумм, дат.

| Токен | Размер | Где |
|---|---|---|
| `--fs-xs` | 11px | заголовки групп меню (uppercase, letter-spacing .08em) |
| `--fs-sm` | 12px | подписи, хинты |
| `--fs-md` | 13px | кнопки, заголовки карточек |
| `--fs-base` | 14px | основной текст, пункты меню |
| `--fs-lg` | 16px | заголовки блоков |
| `--fs-xl` / `--fs-2xl` | 20 / 26px | заголовок страницы |

Начертания: 400 — основной текст и пункты меню, 700 — активный пункт, заголовки, названия действий.

## Ритм и геометрия

- Отступы кратны 4: `--sp-1…--sp-8`.
- Радиусы сдержанные: `--r-sm` 6px (мелкие элементы), `--r-md` 8px (кнопки, пункты меню),
  `--r-lg` 12px (карточки, поповеры), `--r-pill` для индикаторов и скроллбара.
- Каркас: `--sidebar-w` 248px. Верхней плашки нет — экран делится на навбар и контент.
- `--dock-safe` 96px — резерв справа под плавающий докбар. Шапка каждой страницы обязана
  держать этот отступ, иначе кнопки уезжают под островок с темой и уведомлениями.
- Высоты контролов: пункт меню 34px, кнопка 36px, поле ввода 36px.

## Нативные контролы

`.themeRoot` объявляет `color-scheme: dark` (и `light` в светлой теме) — это красит то,
что CSS не достаёт: календарь `input[type=date]`, выпадающие списки, нативные скроллбары.
Без него браузер рисует их белыми поверх тёмного интерфейса.

## Тени и фокус

`--shadow-sm` — приподнятые поля, `--shadow-md` — тосты/дропдауны, `--shadow-lg` — поповеры и модалки.
Тени не используются для декора: плоскость по умолчанию, тень = «слой поверх».
Фокус только через `:focus-visible` + `box-shadow: var(--focus-ring)`, `outline: none`.

## Движение

`--t-fast` (120ms) — цвет фона/текста при ховере. `--t-base` (180ms) — раскрытия, сдвиги.
Никаких scale/bounce на навигации.

## Раскладка главной

Раскладка задана вручную через `grid-template-areas` (3 колонки, строки фиксированной
высоты 220px / 300px «с запасом»), а не автоматическим потоком. Смысл: место каждого блока
известно до отрисовки данных, поэтому при догрузке с сервера ничего не прыгает и не
переставляется. Брейкпоинты: 1180px → 2 колонки, 780px → 1 колонка, для каждого свой `areas`.

Содержимое виджета лежит в `.widgetBody` с `overflow-y: auto` и `overscroll-behavior: contain` —
если данных больше, чем высота строки, скроллится внутренность блока, а не разъезжается сетка.
Вложенные списки собственный скролл не заводят.

## Блоки-контейнеры (виджеты, группы действий)

Блоки **без заливки**: форму держит тонкая пунктирная обводка и радиус `--r-lg`.
Пунктир не пишем руками — только миксины из `styles/_dashed.scss`
(`@import "src/pages/AdminPanel/styles/dashed"`): `dashed-box`, `dashed-box-interactive`,
`dashed-action` (кнопки «+ Добавить»), `dashed-line-top` / `dashed-line-bottom` (разделители).
На ховере обводка становится `--border-strong` — без цветных вспышек. Тени у блоков нет —
приподнятыми остаются только слои поверх контента (докобар, поповеры, тосты).
Заголовок блока — `--fs-md`/700 обычным регистром, под ним разделитель `1px --border`.
Внутри блока не вкладываем ещё одну «коробку»: списки действий — строки, разделённые линией.

## Строка вкладок в рабочей области

Ни выезжающих панелей, ни модалок для длинных форм: всё открывается **вкладками**
в строке в верху рабочей области (`Elements/WorkTabs`) — как в браузере.

- Первая вкладка — сам экран (список), закрыть её нельзя; подпись под заголовком
  показывает контекст выборки («PS · 42 шт.»).
- Действия («Товары», «Парсинг», «Пересчёт цен», «Редактировать», «Новый каталог»)
  открывают свою вкладку; двойной клик по строке таблицы — то же самое.
- Повторное действие по тому же объекту не плодит дубликаты: вкладка с этим `id`
  просто становится активной, её несохранённое состояние сохраняется.
- Вкладки высокие (58px): две строки — заголовок `--fs-md`/700 и подпись `--fs-sm`.
  Ширина 190–300px, длинный текст обрезается, полный виден в тултипе.
- Закрытие: крестик, средняя кнопка мыши, Esc (в полях ввода Esc не перехватываем).
  Закрыли активную — переходим на соседнюю справа, иначе слева, иначе к списку.
- Фоновые вкладки остаются смонтированными и скрываются через `visibility`, а не
  `display: none`: сохраняются прокрутка, введённые значения и страница вложенного списка.
- Правый отступ строки — `--dock-safe`, под плавающий докобар. Экранам внутри вкладок
  этот отступ уже не нужен.

Содержимое вкладки строится через `Elements/WorkTabs/TabPane`: прокручиваемое тело
и закреплённый снизу футер с действиями. Заголовка внутри нет — его роль играет вкладка.
Модальное окно (`Elements/PopUpWindow`) остаётся только для коротких подтверждений
и одноэкранных форм (сейчас — импорт из Excel).

### Правила для содержимого вкладки

Вкладка живёт дольше того рендера, в котором её открыли, поэтому внутрь передаём
**только примитивы (id) и стабильные колбэки** (через `useRef` + `useCallback`).
Иначе вкладка замкнётся на устаревшие поиск, номер страницы или список.

### Раскладка формы внутри вкладки

Формы строятся из `Elements/FormLayout`: `Sheet` (лист шириной до 880px), `Group`
(группа строк с маленьким заголовком), `Row` (строка «подпись слева — контрол справа»),
`Rail` + `Split` (разделы длинной формы слева, показывается только выбранный).

- Никаких «коробок» и двухколоночных сеток полей: строки идут одна под другой,
  разделённые волосяной линией. Высота контролов 30–32px.
- Подсказка живёт под подписью слева, а не под полем — правая колонка остаётся чистой.
- Обычные поля ограничены по ширине (320px); `wide` — на всю строку (textarea, списки, чекбоксы).
- Контекст, который в этой форме менять нельзя (каталог, площадка, страница), показывается
  строкой со значением моноширинным шрифтом, а не заблокированным полем.
- Нижняя полоса действий (`TabPane`) — без фона и рамок, только линия сверху; с флагом
  `narrow` она выравнивается по правому краю листа, чтобы кнопки не улетали к краю монитора.
  Главное действие вкладки живёт там, а не внутри формы.

### Когда вкладка закрывается принудительно

Вкладка не должна вести «в никуда», а список под ней живёт своей жизнью:

- **Смена раздела в навбаре** — маршрут размонтируется, вкладки уходят вместе с ним.
- **Смена страницы (`structurePage`)** в «Каталогах» вкладки НЕ закрывает — они самостоятельные.
  Вместо этого вкладка каталога подписана своей страницей («Playstation Индия · ps_ind_gta6»),
  а форма создания показывает страницу, на которой открыта: там каталог и создастся.
- **Объект удалён** — его вкладки закрываются: сверяем `entityId` с полным списком сущностей,
  а не с отфильтрованной выдачей. Поиск и фильтры открытые вкладки не трогают.
- **Перелистывание вложенного списка** в «Товарах каталога» — закрываются вкладки карточек,
  которых нет на новой странице; закрытие самого каталога уносит их все.
- **Переименование** объекта не закрывает вкладку, а обновляет её подпись (`updateTab`).

Форма внутри вкладки разбита на секции с заголовком `--fs-xs`/700, uppercase, `--text-muted`.

## Плавающий докобар

Управление темой и уведомлениями вынесено из шапки в островок `position: fixed` (top/right `--sp-4`):
скруглённый по `--r-pill`, полупрозрачный `--surface` + `backdrop-filter: blur(12px)`, `--shadow-md`.
Иконки — круглые ghost-кнопки 32px, между смысловыми группами — сепаратор: полоска 1×18px
`--border-strong` с `--r-pill`. Непрочитанные процессы отмечаются точкой 6px `--accent`
с обводкой цвета подложки; если среди итогов есть проблемный, та же точка становится
`--warning` — вторую метку не заводим.

Поповер колокольчика разделён на две секции: «Фоновые задачи» (идут сейчас) и «Итоги»
(завершились). Заголовок второй отделён линией `1px --border`, скроллится содержимое
секций, а не сам островок.

## Блок «Итоги задач»

Процесс исчезает по окончании работы, поэтому итог живёт отдельным блоком, пока его
не закроют крестиком. Строка итога — не карточка: цвет статуса несёт полоска 2px слева
(`--success` / `--warning` / `--danger`), фон остаётся прозрачным. Заливкой статус
не показываем — это спорило бы с акцентом.

Подробности (какие позиции не прошли и почему) скрыты за строкой-раскрытием и грузятся
по запросу: у парса каталога их сотни. Внутри — вид проблемы тегом `--fs-xs`, название
ссылкой на витрину (`--accent`), причина `--text-secondary`, идентификатор `--font-mono`.

## Паттерн навигации

Навбар начинается с бренд-шапки: только название «Админ-панель» `--fs-xl`/700, снизу
разделитель `1px --border`. Никаких логотипов-плашек. Дальше — группы пунктов:

```
[группа]  КАТАЛОГ          ← --fs-xs, uppercase, --text-muted
  Товары                   ← 34px, --text-secondary, radius --r-md
  Каталоги      (активный) ← фон --accent-soft, текст --accent, 2px полоса слева
```

Группы разделяются отступом `--sp-5`, а не линиями. Между пунктами внутри группы — 1px.
Навбар содержит только навигацию: глобальные действия (обновление ассоциаций и структуры)
живут виджетом «Обслуживание» на главной. Акцент в навбаре зарезервирован за текущим разделом.

Активный сегмент переключателей жирнее обычного, поэтому таб резервирует ширину под
жирное начертание (`::after { content: attr(data-label); font-weight: 700; height: 0 }`) —
без этого список сегментов дёргается при каждом переключении.

## Кнопки

| Тип | Фон | Рамка | Текст |
|---|---|---|---|
| Primary | `--accent` (ховер `--accent-hover`) | нет | `--accent-contrast` |
| Secondary | `--surface-alt` (ховер `--surface-hover`) | `--border` → `--border-strong` | `--text-secondary` → `--text` |
| Ghost / icon | прозрачный → `--surface-hover` | прозрачная → `--border` | `--text-muted` → `--text` |
| Destructive | `rgba(var(--danger-rgb), .12)` | `rgba(var(--danger-rgb), .45)` | `--danger` |

Disabled: контур `--border`, текст `--text-muted`, фон прозрачный, `opacity: .6`,
`cursor: not-allowed` — в том числе у primary, чтобы неактивная кнопка не выглядела
залитой серой плиткой.

## Что не делаем

- Градиентные заливки и цветные тени под кнопками.
- Более одного акцентного цвета на экран.
- Иконки в пунктах меню.
- Радиусы > 12px, промежуточные веса шрифта, анимации на hover-трансформ.
